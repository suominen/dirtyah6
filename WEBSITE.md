# Website plan — `https://kimmo.cloud/dirtyah6/`

Publish the DirtyAH6 tracker as a single-page static site, generated by
**Hugo** locally and rsync'd to a personal nginx server (`haig`). The build
infrastructure mirrors the sibling trackers; only the content and a few
config strings differ.

## Architecture

- **Source repo:** `github.com/suominen/dirtyah6` (this repo).
- **Generator:** Hugo extended, ≥ 0.146.0. Run locally; nothing built in CI.
- **Source layout:** Hugo project under `site/`; the tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule).
- **Dev environment:** Nix flake (`flake.nix`) provides hugo + go + git +
  resvg + curl/libarchive/zstd. Auto-activates via `.envrc` with direnv.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/` →
  `haig:/dirtyah6/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/dirtyah6/` at the URL path `/dirtyah6/`.

## Naming — nickname slug (CVE assigned)

The bug carries a name (**DirtyAH6**) *and* a CVE (**CVE-2026-80844**) from
the outset — the name is the one the researcher's PoC and write-up use.
Following the sibling precedent — which runs both ways (ghostlock,
januscape, pintheft, and cifswitch kept nicknames; Dirty Frag was renamed
to `/CVE-2026-43284/`) — the site uses the **nickname** as its slug
everywhere, with the CVE carried in the tracker body, Summary, and title.
The three trackers disclosed alongside it (TUNderflow, PPPoEject,
DiagSpill) follow the same nickname-slug convention.

The site uses `dirtyah6` as its slug everywhere:

- repo: `~/src/dirtyah6`, `github.com/suominen/dirtyah6`
- Go module path: `github.com/suominen/dirtyah6/site`
- URL: `https://kimmo.cloud/dirtyah6/`
- systemd units: `dirtyah6-tracker-update.{service,timer}`

## Tracker content

- One kernel bug, **single verdict axis**: the `7bad4bda74dc` fix is the only
  thing that flips a row. (If the bug has a userspace reachability gate that
  ships as its own package, add a second verdict column — the cifswitch
  two-axis model; see ../DESIGN.md.)
- **Patch status** uses a single combined table for upstream and distros
  (`Distribution | Release | Current kernel | First fixed | Fixed since |
  Status`): the upstream kernel is the first `Linux kernel` group, opt-in
  kernels get their own rows, and per-distro `###` headings appear only
  where there is an audience-relevant note. In the browser the
  Distribution column renders as full-width group heading rows, and the
  column header and group headings are sticky.
- Seed every row from sourced facts — no unconfirmed "fixed" claims.
- Social banner: `site/assets/dirtyah6-tracker.svg` → `.png` via
  `make banner`.

## Decisions

- **Hosting:** own nginx on `haig`, not GitHub Pages.
- **Canonical source:** `site/content/_index.md`.
- **Automated maintenance:** a user-level systemd timer runs
  `scripts/auto-update`, which merges `origin/main` into a long-lived
  `auto-update` branch in a separate worktree and hands off to headless
  Claude. The agent commits onto `auto-update` only. Merges to `main` are
  manual.

## Cross-reference — the disclosure quartet

DirtyAH6 was disclosed on 2026-09-18 by Asim Manizada as one of four
independent Linux local-root bugs embargoed together through
`linux-distros@` and announced in a single
[oss-security post](https://www.openwall.com/lists/oss-security/2026/09/18/3).
Each has its own tracker:

- **DirtyAH6 (CVE-2026-80844)** — this tracker: IPv6 AH6 routing-header
  out-of-bounds write (`net/ipv6/ah6.c`).
- **TUNderflow (CVE-2026-81000)** — TUN receive-headroom underflow;
  `~/src/tunderflow` / <https://kimmo.cloud/tunderflow/>.
- **PPPoEject (CVE-2026-68121)** — PPPoE stale skb-head pointer across
  `dev_hard_header()`; `~/src/pppoeject` / <https://kimmo.cloud/pppoeject/>.
- **DiagSpill (CVE-2026-74469)** — SCTP `sctp_diag` transport-count
  overflow; `~/src/diagspill` / <https://kimmo.cloud/diagspill/>.

They are separate bugs in separate subsystems with separate fixes — do not
merge their status. The cross-links live in the References table, the
Summary's *Related* row, and the CLAUDE.md context. All four share the
first upstream stable releases that carry every fix (5.10.270, 5.15.221,
6.1.188, 6.6.157, 6.12.109, 6.18.50, 7.2.4 per the announcement), but each
tracker keys its own rows on its own fix commit.

## Risks & gotchas

- **Subpath baseURL** must keep the trailing slash and path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not in the build output.
- **Anchor drift:** Hugo/Goldmark's slugger differs from GitHub's; pin
  brittle headings with `### Heading {#stable-id}` if needed.

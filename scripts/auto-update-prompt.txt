DirtyAH6 (CVE-2026-80844) is an out-of-bounds read/write in the Linux
kernel's IPv6 Authentication Header (AH6) code. ipv6_rearrange_rthdr() in
net/ipv6/ah6.c derives the routing-header address count from hdrlen but
never checks segments_left against it; a raw IPv6 HDRINCL packet with
hdrlen=2 and segments_left=255 moves an address pointer 4,064 bytes back
and hands 4,064 bytes to memmove(), corrupting memory past the skb head.
The canonical fix is 7bad4bda74dc (xfrm: ah6: validate routing header segments_left), first released in
v7.3-rc1. The bug was introduced by 1da177e4c3f4 in
v2.6.12, so the reachable window is 2.6.12 through 7.2 without the backport.
DirtyAH6 is one of four local-root kernel bugs disclosed together by the
same researcher on 2026-09-18; the siblings are TUNderflow
(CVE-2026-81000), PPPoEject (CVE-2026-68121), and DiagSpill
(CVE-2026-74469), tracked separately. Keep the four cross-referenced but
do not merge their status — each is an independent bug with its own fix.

Working-tree hygiene: stream a fetch through a pipe — `curl -fsSL <url> |
grep …` — when one pass over the data is enough. If you genuinely need a
scratch file, save it in the worktree under a `.scratch-` prefix (e.g.
`.scratch-advisories.json`), work on it there, and `rm` it before you
commit — never `git add` a scratch file. Write it with `curl -o
.scratch-…` or `… | tee .scratch-… > /dev/null`: a shell redirection into
a file (`> .scratch-…`) is refused by Claude Code even inside the
worktree, and retrying it in another spelling is wasted effort
(`/dev/null` is the one redirection target that passes). Read it back
with an allowlisted reader (`zcat .scratch-x.gz | grep …`,
`jq … .scratch-x.json`).
Don't use /tmp: Bash file reads are confined to the worktree, so a file
there can be written but not read back. The wrapper's `git clean -fd`
sweeps forgotten scratch on the next run, but the only thing you should
leave behind is the edited tracker (and its commit).
